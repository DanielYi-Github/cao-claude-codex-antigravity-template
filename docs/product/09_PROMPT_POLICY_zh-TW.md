# Prompt 安全與拒絕原因

Lyria 會對輸入與輸出執行安全檢查。常見攔截原因包括：

- 指定或暗示模仿特定歌手、作曲家、樂團或聲音。
- 要求現有歌曲、歌詞、旋律或錄音的重製。
- Prompt 可能觸發 recitation checking。
- Prompt 涉及 offensive content 或其他 responsible AI 限制。

本程式的做法不是「繞過限制」，而是避免不必要的參照：

1. 素材庫只保存音樂屬性、場景、樂器、節奏、質感與製作描述。
2. 發送前檢查禁止參照詞。
3. API 回報 safety/artist intent/copyright 類錯誤時，**先照一般錯誤重試**
   （預設 3 次、指數退避）；只有每一次都被擋，才改寫成中性的純器樂屬性描述再試。
4. 不調低、不關閉安全過濾。
5. 多次失敗後停止 job，將原因寫入 SQLite 與 log，可用 `lyria-auto resume` 續跑。

## 為什麼不是一被擋就改寫

實測發現 `400 content_blocked` 有相當比例是**隨機的** —— 完全相同的 prompt
呼叫兩次，一次被擋、一次成功。

早期版本只要錯誤訊息命中 `blocked` / `policy` 等關鍵字就立刻放棄重試、直接改寫 Prompt。
這在隨機失敗的情況下有害：為了一次偶發錯誤就永久換掉那首曲子的內容，
而且改寫後的 Prompt 不會寫回 `plan.json`，導致成品與計畫記載的不一致。

現在改成先重試相同 Prompt，只有持續被擋才判定內容真的有問題。
